# OpenSpec Workflow

This project is developed through OpenSpec changes. Before implementing, identify or create the relevant change under `openspec/changes/` and keep work aligned with its proposal, design, specs, and tasks.

OpenSpec changes should be linked to the relevant Linear ticket when work is tracked externally. Keep ticket references in the change artifacts or implementation notes where useful for traceability.

Never use `openspec/` for anything other than OpenSpec artifacts and architecture decision records.

Use `.todo/` for temporal working documents such as summaries, notes, detailed implementation plans, result lists, checklists, and handoff context. Keep `.todo/` organized with subdirectories named after the relevant OpenSpec change where possible.
